Capabilities

Smart-object compositing, minus Photoshop

🌀

Real warps, not skews

Flat surfaces get true perspective transforms; mugs and bottles wrap cylindrically; shirts and totes ripple with fabric displacement. Shadows and highlights from the photo carry into your artwork.

🎬

Video mockups

Drop an MP4 in as the design and watch it play back on the product inside the plugin. Export the warped clip as an MP4 — encoded locally, nothing uploaded.

♻️

Never lose work

A render only ever swaps the mockup's image fill. Your design frame stays live and editable — tweak and re-render as many times as you like.

Setup

Two pieces: a plugin and its render service

The plugin does the canvas work; a small local service does the pixel work. Both live in this repo.

01

Install and build

Node 20+ required. From the mockupplugin folder:

npm install
npm run build --workspace @mf/shared
npm run seed --workspace @mf/api      # generates the mockup library
npm run build --workspace @mf/plugin
02

Start the render service

Run npm run dev:api and leave it running. Check it's alive: curl http://localhost:8787/health.

03

Import the manifest

In the Figma desktop app, go to Plugins → Development → Import plugin from manifest… and pick apps/plugin/manifest.json.

04

Launch and connect

Run it from Plugins → Development → Mockup Forge. The badge should read Canvas connected, and the Settings tab's Test connection should find your service.

🌐 Custom service URL? Any URL you set in Settings must also be listed in manifest.json under networkAccess.allowedDomains — and Figma rejects IP addresses there, so use a hostname like localhost, never 127.0.0.1.
Workflow

Browse. Drop in. Render.

01

Import a mockup from the Library

Search or filter the grid and click a tile. The mockup lands on your canvas with a design frame beside it — checkerboard fill, correct aspect ratio — plus a colour swatch for each recolourable part.

02

Place your artwork in the design frame

Anything goes: images, text, components, whole layouts. The hint label hides itself at render time. Scale the frame freely — the plugin warns if its ratio drifts from what the surface expects.

03

Set colours (optional)

Recolour the swatch rectangle to change the product itself — a black mug, a navy tee. Shading and texture survive because the tint is applied as a ratio, not a flat fill.

04

Render

Select the mockup (or its design frame — either works) and hit Render selected in the Render tab. Seconds later the product photo updates with your artwork warped on. Select several mockups and Render all does them in one pass.

🔗 Rename anything, move anything. The link between a mockup and its design frames lives in plugin data on the nodes, not in their names — the [MF] prefixes are just labels.

The preview is the export

Select a mockup, hit Choose clip… on its card, and pick an MP4, MOV, or WebM up to 30 seconds. The plugin decodes it, warps every frame onto the product, and encodes a fresh MP4 — which plays right there in the panel.

  • Download MP4 saves exactly what you just watched
  • Apply poster to canvas pins the first frame onto the mockup, since Figma can't play video on canvas
  • Pick 12 / 24 / 30 fps, and whether the clip fills the surface (crop) or fits inside it (letterbox)
  • Encoding is local WebAssembly H.264 — the clip never leaves your machine except as frames sent to your own render service
Growing the library

Add your own mockups from a photo

01

Shoot or source the photo

2000–4000px, even lighting, and — most important — the print surface blank. A pure white surface is ideal: the authoring tools can then find it automatically.

02

Click the corners

Open tools/pick-points.html in a browser, load the photo, and click the surface corners in design order. It hands you the coordinates, normalized and ready.

03

Author the item

npx tsx tools/author-item.ts \
  --id desk-poster-01 --name "Poster on Desk" \
  --category print --viewpoint scene \
  --base ~/photos/desk.jpg \
  --corners "0.21,0.18 0.78,0.25 0.74,0.82 0.19,0.75" \
  --aspect 0.7071

Masks, shadow and highlight maps are derived from the geometry, so they can't disagree with the warp. Curved surfaces use --rect with --cylinder; fabric adds --fabric --displacement.

04

Restart the service

The new item appears in the Library tab immediately. Render it against the test grid with npx tsx tools/render-sample.ts your-item-id to sanity-check the warp.

Configuration

Two knobs. Sane defaults.

SettingDefaultGuidance
Render service URL http://localhost:8787 Where the catalog and renders come from. Remembered per user. Must be in the manifest's allowed domains.
Render width override full resolution Lower it (e.g. 960) for fast previews while iterating; clear it for the final full-res render. Also caps video export size.
📐 Aspect ratios are the contract. Design frames can be any size — the render keys off ratio, not pixels. Drift beyond 2% gets a warning naming the exact frame height that would fit, and renders anyway (stretched) unless you fix it.
⏱ Speed: stills render in well under a second. A 10-second video is a few hundred frames — expect roughly half a minute, with per-step progress in the panel.
Troubleshooting

When something looks off

Stuck on “Connecting to the canvas…”

Rebuild the plugin (npm run build --workspace @mf/plugin) and reopen it — Figma caches the old bundle until relaunch. If it persists, open Plugins → Development → Show/Hide console and look for [MF] lines.

“Cannot reach the render service”

Check the service is running (curl http://localhost:8787/health) and that the URL in Settings uses a hostname that's listed in the manifest — Figma silently blocks any other origin, and blocked looks identical to offline. Thumbnails failing while the list loads means the same thing.

The library grid is empty

The catalog is generated, not committed. Run npm run seed --workspace @mf/api, restart the service, and refresh the Library tab.

My artwork looks stretched on the product

The design frame's ratio has drifted from what the surface expects — the Render tab shows the drift percentage and the exact pixel height to restore. Resize the frame and re-render.

The render replaced my design!

It can't — renders only touch the mockup frame's image fill. Your design frame is untouched next to it; it may just be hidden behind the updated mockup. Renaming or moving frames is also safe: the binding lives in plugin data, not names.

The video export has no sound

Correct — v1 exports are silent by design. Audio passthrough is on the roadmap (see docs/VIDEO.md); until then, remux the audio from your source clip in any editor.

Renders suddenly return “rate limited”

The service allows 30 renders per minute per IP as abuse protection. Batch video requests count once per batch, so normal use rarely hits it — wait a moment and retry, or raise RATE_LIMIT_RENDERS on your own service.
