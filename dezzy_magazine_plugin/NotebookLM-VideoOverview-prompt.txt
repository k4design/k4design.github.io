Create a tech product-launch presentation video for Dezzy Magazine, the
property-magazine engine for Figma — the energy of a keynote stage reveal, not
a tutorial. The presenter is confident and precise, unveiling a product they
built and are proud of. Audience: design teams and real-estate marketing
leads seeing it for the first time.

CRITICAL FRAMING RULE
Present the product itself. NEVER mention the source material — no "the
guide", "the document", "this PDF", "the figure", "the screenshot", or "as
shown in". The interface images from the source are your on-screen demo
visuals; refer to them only in product terms ("here on the Photos tab…").
Don't invent or generate any other UI.

VOICE
Keynote cadence: short declarative sentences, the benefit first and then the
engineering, and let the numbers land as punchlines — "a hundred pages…
one undo step." Use the product's tagline as a refrain: "Tag once. Pour
forever."

STRUCTURE — follow the source's act structure:
1. COLD OPEN — the problem: every listing means rebuilding a hundred-page
   magazine by hand. Then the reveal: Dezzy Magazine. Tag once, then every
   listing is fill a form, drop in the shoot, click Apply. Name the five
   tabs: Tag, Content, Photos, Apply, Bulk.
2. ACT I — Teach your template (once): auto-numbering with automatic spread
   detection; layer names becoming tags; the room-category system; surgical
   hand-tagging; {{field}} text templates; coupling spreads; locks; the Tag
   index; renaming layers to match. Tags survive duplication and propagate
   into component instances.
3. ACT II — Feed it a listing: the Content form with live tag counts and
   CSV round-trip; then the photo engine (see mandatory beats below).
4. ACT III — The apply moment: dry run and magazine check (including spread
   drift), then the one-click apply, then applying from any tab.
5. ONE MORE THING — save state: the entire listing (values, photos,
   assignments, tags) in one zip; plus retag-from-images.
6. CLOSE — recap and tagline.

MANDATORY FEATURE DEEP-DIVES — each of these must get its own explained
moment, with the specific details, not a passing mention:
• THE PHOTO TAG HIERARCHY: fifteen room categories recognized in BOTH layer
  names and photo filenames; first match wins; bath outranks bedroom, so
  "Master Bath 2" is never mistaken for a bedroom; interior and exterior are
  POOLS that draw from every room and may repeat photos.
• AUTO-ASSIGN'S FOUR PASSES: full-page slots consume the shoot in
  room-progression order (porch → living → kitchen → dining → master →
  master bath → … → exterior — the order a magazine walks a house); then
  filename-to-category matches; then the interior/exterior pools, preferring
  unused photos; then everything else into numbered slots in filename order.
  Named slots — cover, hero, agent — always stay human.
• THE IMAGE PIPELINE: photos process one at a time so peak memory is about
  one image regardless of batch size; pixels stay untouched unless a photo
  exceeds Figma's hard 4096-pixel ceiling — only then downscaled as JPEG at
  quality 90 to protect print; WebP/AVIF converted automatically; every file
  deduplicated by content hash; and the invisible image vault pins every
  photo's bytes into the file so Figma's garbage collector can't destroy an
  unplaced shoot.
• THE SPREAD ENGINE: coupled spreads are cover-fit to the COMBINED bounding
  box of both frames across both pages, each half getting its exact crop
  window — zero duplicated pixels, zero missing pixels, gutter accounted for.
• THE APPLY ENGINE: fonts deduplicated and preloaded once, yields every ten
  layers so Figma stays responsive, dead tags self-heal, missing fonts are
  reported never fatal, unassigned slots flood magenta, and the entire run is
  ONE undo step, cancellable mid-flight.

Don't turn the closing field-notes table into a segment — at most one line
that the plugin flags its own problems.
