Capabilities

Judgement, not just scraping

👁

Reads the picture, not the caption

Explore prompts are often vague or plainly wrong about what ended up in frame. Every image goes to Claude as an image and is judged on what it actually shows.

◱

Cheap to look, full-res to keep

Judging runs on 384px thumbnails — a couple of hundred tokens each. Only the images that pass get downloaded, at native resolution.

⏱

Runs to a budget

Set how many matches you want plus hard ceilings on images scanned and minutes elapsed. Whichever arrives first ends the run.

Setup

Load it unpacked

There's no Web Store listing — the folder is the extension, so Chrome needs developer mode.

01

Find the folder

The extension lives at k4design.github.io/mjscraper. Nothing to build. Keep it somewhere permanent — Chrome reads it from this path on every launch, so moving or deleting it breaks the extension.

02

Turn on developer mode

Paste chrome://extensions into the address bar — it can't be reached from a link — and switch on Developer mode, top right. Without it there's no load-unpacked button.

03

Load unpacked

Click Load unpacked and select the mjscraper folder itself, not a file inside it. The icon appears in your toolbar — pin it so it's one click away.

🔄 After any code change, hit reload. Editing files on disk does nothing until you press the reload icon on the extension's card in chrome://extensions. This catches everyone at least once, and it's mandatory whenever the permission set changes.
First run

Two things to set, once

The second one is the difference between a hands-off run and clicking a dialog for every single image.

01

Add an Anthropic API key

Click the toolbar icon to open the side panel, expand Anthropic API key, and paste your own. It's kept in the extension's local storage on this machine and sent only to api.anthropic.com.

Every Claude call is made from the background worker, so the key never touches a web page. Ask Kyle if you need a key of your own — don't paste someone else's, and never commit one to the repo.

02

Stop Chrome asking where to save

Open chrome://settings/downloads and turn off "Ask where to save each file before downloading". Leave it on and you get a Save-As dialog per matched image — twenty matches, twenty clicks.

While you're on that page, check the download location. A long run puts a few hundred files under it.

⚠ That setting is global. Normal browsing downloads stop prompting too. It overrides anything the extension asks for and can't be bypassed per-download, so the choice is switching it off while collecting or keeping the clicks. The per-run subfolder at least keeps images corralled instead of loose in Downloads.
Workflow

Describe. Start. Walk away.

01

Open a feed that paginates

Go to midjourney.com/explore and pick Hot, Top, or For You. Avoid Random — it holds a fixed set of about 26 images and never loads more, so a run there is over almost immediately.

Close DevTools on that tab if it's open. Scrolling needs Chrome's debugger connection and only one client can hold it.

02

Open the side panel

Click the toolbar icon. The panel docks beside the page and stays for the whole run, so progress and Stop are always reachable — a popup would close the moment focus moved, which happens constantly while the feed is being scrolled.

03

Describe the subject and set limits

Plain words: a lone figure in fog, brutalist concrete stairwell, hand holding a ceramic mug. Specific beats broad — judging is strict by design, so a loose subject collects loosely. "Fog" matches any misty landscape; "a lone figure in fog" doesn't.

Then set Want, Max cards, and Max min. On a new subject try 5 / 40 / 2 and look at what lands before scaling up.

04

Press Start, then leave the tab alone

The feed scrolls itself, images go off for judging six at a time, and matches download as they're found. Progress, running cost, and a per-batch log update live. Stop halts within a scroll or two and finishes cleanly.

🐞 Chrome will say it's being debugged. A yellow "MJ Explore Grabber started debugging this browser" banner sits across the top for the length of each run. That's expected and unavoidable — see the FAQ. It clears when the run ends.
🔍 Check saved against matched. If the panel reports matches but the saved count lags, files are failing to write rather than quietly succeeding. The log names a reason per image.

Named after what's in them

The explore grid doesn't expose prompt text — only a job id. So rather than chase a prompt that may not describe the picture anyway, the same Claude call that judges each image also returns a short description, and that becomes the filename.

  • Saved as mj-<subject>/<description>-<id>.png
  • The id fragment means two similar images can't collide
  • Names reduce to letters, digits and dashes — safe on any filesystem
  • Judged six at a time, two batches in flight
  • Only matches download; a skip costs one thumbnail and nothing else
📐 "Full size" means native. Downloads are the largest file MidJourney holds, typically 816×1456. Asking for anything larger returns the same pixels — it's a ceiling, not a setting.

Troubleshooting

When something looks off

Chrome asks where to save every single file

Turn off Ask where to save each file before downloading at chrome://settings/downloads. The extension already requests a silent download, but that browser setting overrides the request and there's no way for an extension to win against it per-download.

It says it's running, but nothing scrolls and nothing turns up

Almost always the Random tab, which doesn't paginate — switch to Hot, Top, or For You.

Otherwise the extension needs reloading in chrome://extensions after a code change, and the tab you started from must be the explore page: the run drives whichever midjourney.com tab was focused when you pressed Start.

"Close DevTools on the explore tab first"

Scrolling needs Chrome's debugger connection and only one client can hold it at a time. Close DevTools on that tab and press Start again.

Why does it need to debug my browser?

MidJourney only loads more images in response to genuine input events. Setting the scroll position directly moves the view all the way to the bottom without loading a thing, and a synthetic wheel event doesn't move it at all — the page ignores both.

Chrome's debugger API is the only way an extension can produce input the page treats as real. That's the entire reason for the permission and the banner. It dispatches wheel ticks into the explore tab and does nothing else, and it detaches the moment the run ends.

It scans plenty but matches almost nothing

Usually the subject is narrower than the feed. Judging is strict on purpose — a loose thematic association doesn't count — so broaden the wording or run against a feed likelier to contain it.

Check the log too: a refused batch is recorded there and skipped rather than matched.

Matches are counted but the saved count doesn't keep up

Downloads are failing rather than silently succeeding, and the log names a reason per image. Confirm the download directory still exists and is writable.

MidJourney's image server also rejects requests that don't look like they came from a browser, which is the most likely place this bites. Send the log lines to Kyle — the fix is routing downloads differently, not a setting you can change.

Too many near-misses get through

Tighten the subject before reaching for a better model. "Fog" will match any misty scene; "a lone figure walking in thick fog, seen from behind" won't. If the wording is already precise, move up to Opus 5.

The panel disappears mid-run

It shouldn't — the side panel stays until you close it. A small window that vanishes when you click the page means you're on an older build with the popup UI; reload the extension.

Either way the run itself survives, because progress lives in the background worker rather than in the panel.

Can I run two collections at once?

No. One run at a time, in one tab. Starting a second replaces the first, and the debugger can only drive one tab anyway.

Are these images mine to use?

No. Explore images are other MidJourney users' generations, and the site's terms restrict automated collection. This automates gathering visual reference you could already save by hand, one file at a time, from your own logged-in session.

What you do with the folder afterwards — particularly anything you publish or hand to a client — is your call and your responsibility.
