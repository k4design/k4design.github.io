How it works

Running a shoot list through MidJourney is mechanical work: paste a prompt, hit Enter, wait for the bar to clear, paste the next. Fifteen variations of the same product shot is fifteen rounds of it, and the moment you tab away to do something else the batch stalls. This extension takes the whole list as one string, splits it on $, and types each prompt into the prompt bar in sequence — without waiting for any job to finish, because MidJourney already queues them itself.

$

One string, many prompts

Split on $. Leading, trailing and doubled separators are ignored, so a stray $ costs you nothing.

⤓

Fire and forget

No waiting on job completion. Prompts go in back to back at a delay you set, and MidJourney's own queue takes it from there.

◍

Stays on screen

A rail docked to the side of the page, not a Chrome popup — so it doesn't vanish the moment you click elsewhere. It's there until you close it.

Once per machine

Install

It's an unpacked extension — no Chrome Web Store listing, so it loads straight from a folder on disk.

1

Unzip it somewhere permanent

Chrome loads the extension from this folder every launch, so don't put it in Downloads and tidy up later — if the folder disappears, the extension breaks.

2

Open the extensions page

Go to chrome://extensions and turn on Developer mode with the toggle in the top right. The Load unpacked button only appears once that's on.

3

Load unpacked

Click Load unpacked and select the folder containing manifest.json. Pick the folder itself, not the file inside it.

4

Open MidJourney and reload the tab

Go to midjourney.com/imagine and reload. This step is not optional: the extension attaches only to pages loaded after it was installed, so an already-open tab won't have it.

5

Pin the toolbar icon

Click the puzzle-piece icon in Chrome's toolbar and pin Midjourney Prompt Injector. You don't need it to use the panel — the panel appears on its own — but the icon is how you bring it back after clicking ✕.

⚠After any update, close your MidJourney tabs. Reloading the extension while a tab is open leaves the old code running in that page as an orphan — it keeps going but can't talk to the rest of the extension, and you'll see Extension context invalidated in the console. Close the tabs, reload the extension, then open a fresh tab.
Once per batch

Write the list

The whole input is one line of text. Everything hangs on the separator.

1

Join your prompts with $

Spaces around the separator don't matter — a $ b and a$b both give two prompts. Whitespace at each end is trimmed and empty entries are dropped.

  • Everything else passes through verbatim, including --ar 16:9, --v 6.1, --no, weights and image URLs
  • Commas, quotes and apostrophes are all safe — $ is the only reserved character
  • A single prompt with no $ in it works fine
2

Check the count before you start

The panel reads N prompts detected as you type. If that number doesn't match what you expect, you have a missing or doubled separator — fix it before running, not after.

3

Set the delay

Two seconds is the default and suits most batches. It's the pause between one submission and the next, not a wait for anything to finish.

✎Your draft is saved. The prompt box, the delay, which side the rail is docked to, and whether it's collapsed all persist, so you can exit, come back, and carry on without retyping or rearranging.

Reading the run

The queue runs in the page rather than in the panel, so the counter keeps advancing whether the panel is on screen, collapsed, or closed. Each finished prompt lands in the list at the bottom with one of two outcomes:

  • submitted — the text landed in the prompt bar and Enter was dispatched
  • failed — with the reason attached; the queue carries on to the next prompt

Pause stops before the next submission and holds; anything already sent to MidJourney keeps generating, because there's nothing to call back. Stop ends the run and clears the queue.

The rail is docked to the right edge and runs the full height of the window. ⇄ moves it to the left if it's covering something. – collapses it to just the title bar, which is the usual move once a run is going. ✕ exits; mid-run it asks whether to leave the queue running or stop it, rather than guessing.

Reloading the MidJourney tab kills the run. The panel comes back with the prompts that never got sent already loaded, so you can pick up where it stopped instead of working out which ones made it.

Worth knowing

Reference

Three behaviours that look like bugs and aren't.

01

Params vanish from the bar

MidJourney lifts --ar and --v out of the text into its own controls the moment you type them. The prompt bar reading back differently from what was sent is normal and is not treated as a failure.

02

"submitted" ≠ "generating"

The extension confirms the text landed and that Enter was dispatched. It deliberately doesn't verify MidJourney accepted the job — that's what makes it fast, and it's why a plan limit can silently swallow prompts.

03

Concurrent job limits still apply

MidJourney caps how many jobs run at once by plan tier. Fire fifteen prompts in thirty seconds and the overflow is rejected by MidJourney, not by the extension. Raise the delay to spread them out.

When something's off

Troubleshooting

Symptom, then cause and cure. Console messages are prefixed [mj-injector].

The rail isn't on the page

Reload the tab — it appears on every page load, so a reload always brings it back. Or click the toolbar icon, which toggles it. If clicking the icon flashes ↻ on the badge instead, the tab predates the extension: reload it. If it flashes MJ?, you're not on a midjourney.com tab.

Start is greyed out

The prompt box is empty, or a run is already going. The count line under the box tells you how many prompts it can see.

Typing in the panel triggers MidJourney's shortcuts

The rail stops keyboard events from reaching the page, but it can't stop listeners MidJourney registers in the capture phase on document. If a keystroke leaks through, report it — the fix belongs in the extension, not your typing.

The rail is covering something I need

Click ⇄ to dock it to the other side, or – to collapse it to the title bar. Both are remembered. It overlays the page rather than squeezing it, so Midjourney's own layout is never altered.

Nothing happens after the first prompt

Almost always an orphaned old copy: the extension was reloaded while the tab stayed open, so the page is still running the previous build. Close every midjourney.com tab, hit Clear all on the extensions Errors page, reload the extension, then open a fresh tab. If it recurs on a genuinely clean load, the page console will name the reason.

"Input bar not found"

MidJourney moved or renamed the prompt bar, so SEL.inputBar in selectors.js no longer matches. The run stops immediately rather than spinning through the queue. Run mjDiagnose() to see what's matching and repair the selector.

"Text did not land in the input bar"

The field was found but rejected the text — usually because MidJourney disabled it, which happens when an account is out of fast hours or at its job cap. Check the site's own status message, then retry the remaining prompts.

Every prompt says submitted, but fewer images appear

Not an extension problem — the prompts went in faster than your plan allows concurrent jobs, and MidJourney dropped the overflow. Raise the delay so the batch spreads out past your cap.

The prompt count is wrong

A literal $ inside a prompt splits it. There's no escape sequence — if a prompt genuinely needs a dollar sign, run that one by hand.

"Extension context invalidated" in the console

The signature of an orphaned content script from a previous build. Harmless in itself, but it means the page is not running the current code. Close the tab and open a fresh one.
