How it works

Building a listing campaign by hand means opening the reference, duplicating it, renaming, re-dating, re-grouping, stripping eight audience segments one by one, and retyping the geography — twenty minutes of clicking where one slip targets the wrong market. This automation does all of it in about thirty seconds, then a human checks it and presses the only button that matters.

◆

The spec is written for you

Claude reads the order and writes the full build spec — budget with reasoning, feeder-market geography, verbatim audience lists — as a monday update.

◆

The campaign is built for you

The reference campaign is cloned via the StackAdapt API, renamed, flighted for 30 days, dropped into the right tier group, audience stripped, geo set.

◆

Activation stays human

The automation cannot activate, resume, or delete anything. Every campaign lands inactive and waits for a person to QA it and click go.

Under the hood

The pipeline

One Vercel function, two routes — /api/spec/display and /api/spec/billboard — fired by monday webhooks on the Listing Orders board.

1

monday fires the webhook

A status column on the Listing Orders board flips to Design Approved. monday calls the function for that channel. Duplicate flips within ten minutes are ignored.

2

The order is pulled

Property address, tier, agent, price, Air asset link, and the property-page click destination come off the monday item. The matching reference campaign is read from StackAdapt.

3

Claude writes the spec

A locked-down prompt produces the build spec: naming, 30-day flight, budget with stated reasoning, feeder-market geography, and the keep/strip audience lists written out verbatim — the model is forbidden from inventing segment names.

4

StackAdapt builds the campaign

The reference is cloned with copyCampaigns straight into the tier's campaign group. One upsertCampaign call then renames it, sets the flight dates, strips the audience (by IDs read off the clone itself), and applies the geography resolved from the spec.

5

Everything posts back to monday

The spec, the build log, and a numbered "remaining by hand" list land as an update on the original task. If any step failed, the update says exactly which piece needs hand-finishing.

⚠The hard rules. The code physically cannot activate, resume, unpause, delete, or archive anything in StackAdapt. It also refuses to create a campaign whose name already exists. These are load-bearing — no future edit removes them.
Every listing

Trigger it

There is no app to open. The trigger is the board you already use.

1

Fill the order like normal

Tier, price, agent, Air link, and property page link on the Listing Orders item. The automation flags anything missing or ambiguous at the top of the spec instead of guessing.

2

Flip the channel's status to Design Approved

The Digital Ads and Billboard columns each have their own automation — flip one or both. About thirty seconds later the update appears on the item.

3

Work the "remaining by hand" list

Open the new campaign in StackAdapt, upload the creative from the Air link, QA everything against the spec in the update, then activate. That final click is always yours.

What comes back

Reading the update

Every update has the same three layers. Read top to bottom.

01

Flags first

Ambiguous price, missing tier, absent links — anything the automation refused to guess sits in bold at the very top. Resolve these before trusting the numbers below them.

02

The spec

The complete build document: clone source, name, flight, budget with reasoning, geography with reasoning, and the full keep/strip audience lists. This is the QA checklist for the built campaign.

03

The build report

What actually happened in StackAdapt: the new campaign ID, what was set automatically, what fell back to by-hand, and the numbered remaining list. "CAMPAIGN CREATED, NOT ACTIVE" is the success line.

Worth knowing

Reference

The behaviour that surprises people.

01

Everything degrades to by-hand

If the audience read, geo lookup, or flight read fails, that one piece is left for a human and the update says so plainly. A partial failure never kills the build or sends a half-payload.

02

Audience strips by ID, not by name

The strip list is matched against segments read off the clone itself, and survivors are echoed back by ID. Invented or paraphrased segment names are structurally impossible.

03

Duplicates are refused

Re-flipping a label for a property that already has a campaign posts "CAMPAIGN ALREADY EXISTS" and touches nothing. Rename or archive the old one by hand first if a rebuild is intended.

When something's off

Troubleshooting

Symptom, then cause and cure.

The label flipped but no update appeared?

Either the flip was a duplicate within ten minutes (ignored by design), or the monday webhook is pointed at a stale URL. Check the board's automations and the Vercel deployment logs.

The update has a spec but no build section?

STACKADAPT_WRITE_ENABLED isn't the exact string true in Vercel, or the env var changed without a redeploy. Env changes only apply after redeploying.

It says "GEO NOT SET - set by hand"?

The market name in the spec didn't resolve to exactly one StackAdapt location — usually a naming mismatch. Set the geography manually per the spec; the rest of the build is unaffected.

It says "CAMPAIGN ALREADY EXISTS"?

A campaign with this property's name is already in StackAdapt, likely from an earlier flip. If a rebuild is intended, rename or archive the existing one by hand, then flip the label again.

It says "AUTOMATION ERROR"?

Something failed mid-build. Nothing was activated. Check StackAdapt for a partially-configured copy of the reference (it may need hand-archiving), read the error in the update, and flag Kyle.
