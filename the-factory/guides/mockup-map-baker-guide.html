Mockup Map Baker — operator's guide covering installing the Photoshop panel, baking displacement, shadow and highlight maps from a product photo, and wiring them into a Mockup Forge item.

Real folds. Real light.
Straight off the photo.

Mockup Forge ships shadow and highlight maps drawn as flat gradients — they know nothing about where the creases in your garment actually are. This panel reads the real product photograph and bakes the three maps the renderer wants, then wires them into that item's item.json for you.

01What this fixes

Mockup Forge takes your artwork and warps it onto a product photo. How convincing that looks depends almost entirely on three greyscale images sitting next to the photo in the catalog.

Two of those three are currently fake. The catalog generates its shadow and highlight maps as SVG gradients — a four-stop linear ramp across the surface, and one blurred diagonal streak. They contain no information from the photograph at all. So your artwork gets the same generic shading whether the shirt underneath is smooth or deeply creased, and the highlight lands wherever a constant said it should rather than where the light actually hits.

Photoshop already has the real photo open. This panel reads it and derives the maps from what is genuinely there.

DISPLACE

Where the surface bends

Pushes each pixel of your artwork along the slope of the fold it sits on, so a logo sinks into a crease instead of floating over it.

SHADOW

Where the light falls off

The real lighting across the product, multiplied onto your artwork — plus the darkening in every fold valley.

HIGHLIGHT

Where it catches the light

Screened on top, black everywhere except the genuine speculars. Matters most on gloss: screens, bottles, vehicle paint.

i

Not a normal map. Mockup Forge has no normal-map or ambient-occlusion code path — nothing in its renderer reads either one. The three maps above are the complete set it understands per surface, alongside the alpha mask that the authoring tool already generates from the warp geometry.

02Install

This is a Photoshop UXP panel, not a Figma plugin, so it does not come from the Figma Community. It loads from the repo through Adobe's developer tool.

Once per machine

  1. Install the UXP Developer Tool.

    Open the Creative Cloud desktop app, search the app list for UXP Developer Tool, and install it. It is free.

  2. Turn on developer mode in Photoshop.

    Photoshop → Settings → Plugins → Enable Developer Mode then restart Photoshop. Without this the tool connects but the panel never loads.

  3. Build the panel.

    The panel runs a generated bundle, so this has to happen before the first load and after every code change.

    terminal
    cd ~/Documents/GitHub/k4design.github.io/displacementmap
node tools/build.mjs

    It prints a build id such as build 1be3978d. Keep that — the panel shows the id it is actually running, which is how you tell whether Photoshop picked up your changes.

  4. Add the plugin in the UXP Developer Tool.

    Add Plugin, then pick manifest.json in that same folder. Click Load.

  5. Open the panel.

    Plugins → Displacement Maps in Photoshop. The top of the panel should read Ready — choose a Mockup Forge item folder (build …).

!

After any change, unload and load again — not Reload. Reload picks up JavaScript, but changes to index.html or manifest.json (panel size, for instance) are only re-read on a full load.

03Before you bake

Two things have to be true, and both are easy to get wrong in a way that produces plausible-looking but wrong maps.

Open the item's own base.png

Not the source photo, not a retouched copy — the base.png inside the item folder. It is already at exactly the item's canvas size, and it carries no artwork, which satisfies the second rule for free.

mockupplugin/assets/items/tshirt-marina-01/base.png

The mockup must be blank

The panel separates geometry from lighting by subtracting a heavily blurred copy of the image. That removes broad lighting falloff — measured at a 22× reduction on a full-width gradient — but it is a low-frequency subtraction. A printed logo already in the photo is sharper than the cutoff, so it survives and gets baked in as geometry that does not exist.

×

No radius setting fixes this. Logos and fabric folds occupy overlapping spatial scales, so any radius aggressive enough to erase a print also erases the folds you are trying to capture. If you only have a printed photo, mask the print out and content-aware fill it before baking.

04Tour of the panel

Four numbered steps top to bottom, a status line above them, and everything else folded away. The status line is the one to watch — it is where every error, every progress message and the build id appear.

ControlWhat it is
Status lineTop of the panel, tinted green on success and red on failure. Height-capped, so a long message scrolls inside itself rather than pushing the controls off-screen.
Document lineWhich Photoshop document will be baked, and its pixel size. Cross-check this against the canvas size reported in step 2.
1 — MaterialWhat the surface is made of. Sets every parameter at once. See Materials.
2 — Mockup Forge itemThe item directory. Reads its item.json and reports the item name, canvas size and surface count.
3 — SurfaceWhich printable area on that item these maps describe. Populated from the file itself.
4 — BakeGenerate Maps. Writes three PNGs and patches item.json.

i

Why "Surface" appears twice in spirit. Step 1 is the material — cloth, paper, paint. Step 3 is the surface — which region of this particular product. A van has one material and four surfaces.

05Bake a surface

Every time

  1. Open the item's base.png.

    The document line at the top of the panel should show its name and size.

  2. Pick the material.

    Fabric, paper, device screen, signage or vehicle wrap. The line underneath describes what that choice keeps and discards.

  3. Choose the item directory.

    Choose… then select one item folder — the one containing item.json and base.png. Not the items folder above it, and not a general output folder. Photoshop asks for file access the first time; the choice is remembered afterwards.

    mockupplugin/assets/items/van-sprinter-01

    The status line should turn green: Loaded Sprinter Van. Pick a surface, then Generate.

  4. Pick the surface.

    The dropdown now lists the surfaces this item actually defines. The van has four — side, grill, hood, front. Your choice sets the output filenames.

  5. Generate Maps.

    A few seconds. The status line reports each stage, then lists what it wrote.

!

One bake per surface. Multi-surface items need the whole loop repeated for each one — four passes for the van. Each pass writes its own three PNGs and patches only that surface's entry in item.json.

06What you get

Everything lands in the item folder you chose. For surface chest on a 1456×816 item:

FileSizeContent
displace-chest.png728×408RG vector field. 128 is neutral on both axes; red drives X, green drives Y.
shadow-chest.png1456×816Multiply map. White is neutral, dark is shaded.
highlight-chest.png1456×816Screen map. Black is neutral, white is blown out.
item.json—Patched in place to point at the three files above.
item.json.bak—Your original, byte for byte.

The two polarities are opposites and easy to confuse when you open them: a correct shadow map is mostly white, a correct highlight map is mostly black.

i

The sizes are load-bearing. The renderer indexes shadow and highlight by canvas coordinate, so they must match the item's canvas exactly — a map one pixel out reads past the row stride and skews. Displacement is sampled in normalized space, so it is written at half canvas to match the rest of the catalog. The panel enforces both.

How item.json changes

The surface's existing warp is promoted to a displacement warp that wraps it. Nothing is re-derived — your authored corners or mesh points are nested verbatim as the new geometry, and every other key in the file is untouched.

item.json — the patched surface
"warp": {
  "kind": "displacement",
  "geometry": { "kind": "homography", "corners": { … } },   ← your original warp, verbatim
  "map": "displace-chest.png",
  "scale": 12,
  "vector": true
},
"lighting": {
  "multiply": "shadow-chest.png",   "multiplyOpacity": 1,
  "screen":   "highlight-chest.png", "screenOpacity": 1
}

Strength is baked into the pixels rather than the opacities, so the opacities stay at 1 and what you see rendered matches what the panel produced. Re-baking the same surface is idempotent — the geometry does not nest inside itself a second time.

!

Masks are deliberately not generated. The Mockup Forge authoring tool derives the alpha mask from the warp geometry specifically so the two cannot disagree. A mask guessed from luminance would reintroduce exactly that disagreement and let artwork bleed off the surface.

07Materials

The material sets nine parameters at once. The one that matters most is high pass, which decides what counts as shape and what counts as lighting. Its 50% cutoff sits at a wavelength of roughly six times the radius, measured at the 2048px reference edge.

MaterialHigh passDisp. scaleAOHighlightBest for
Fabric / apparel1281224 / 1.20.35 @ 0.93Tees, hoodies, totes. Keeps weave, creases and folds.
Paper / print192616 / 0.80.30 @ 0.94Cards, posters, packaging. Keeps gentle bends in the sheet.
Device screen03off0.55 @ 0.88Phones, laptops. The shading is the curvature, so nothing is subtracted.
Signage / wall64812 / 1.50.25 @ 0.95Brick, concrete, billboards. All texture, no broad shape.
Vehicle wrap192520 / 1.00.60 @ 0.90Vans, cars, trucks. Panel curvature and door seams.

Two that look wrong but aren't

Vehicle has the smallest displacement scale despite being the largest object. Panel gaps are near-vertical steps, and a large scale tears graphics apart at every door seam instead of bending them over it.

Vehicle has the largest high pass, tied with paper. The broad curve of a body panel is real shape that artwork has to follow, so it must survive; only the overall lighting gets dropped. Anything lower flattens the panel and the wrap reads as a flat decal.

i

These are reasoned, not measured. They come from how each surface behaves, not from fitting against renders. Expect to tune them against a real render and fold the result back into src/presets.js.

Advanced parameters

FieldWhat it does
High passRemoves broad lighting so shading isn't baked in as fake bulges. Below ~64 it erases fabric folds too. 0 turns it off.
SmoothSoftens the height field so displaced artwork doesn't get jagged edges.
AO radius / strengthSize and depth of the crevices that get shaded. Radius 0 skips occlusion entirely.
Displacement scaleBecomes warp.scale in item.json, in canvas pixels. Raise it if the effect is too subtle — no need to re-bake the PNGs for this alone.
Shadow strength / gammaHow much the real lighting darkens artwork, and how contrasty that shading is. Gamma above 1 reads as more three-dimensional.
Highlight strength / thresholdHow bright the speculars blow out, and the brightness percentile that counts as one. Raise the threshold if too much of the surface glows.
Flip YReverses the vertical displacement direction. See the sign check below.

Radii are written at a 2048px reference and scaled to whatever the actual image is, so a material behaves the same on any item size.

08Check the result

The panel cannot tell you whether the maps look good — only whether they were written. Render the item to find out.

terminal
cd ~/Documents/GitHub/k4design.github.io/mockupplugin
npx tsx tools/render-sample.ts
npm test --workspace @mf/api

render-sample.ts composites a procedural grid test card onto every catalog item and drops the results in assets/samples/. A grid is the right test image because any warping shows up immediately as bent lines.

!

Check the displacement direction before anything else. Which sign is correct cannot be worked out on paper — it is whichever makes artwork sink into folds rather than climb out of them. Look at the sample. If it is inverted, toggle Flip Y in the panel and bake again.

The golden-image tests will now fail for any item you baked, because the rendered pixels genuinely changed — that is the entire point of the change, not a regression. Inspect the .diff.png, confirm the shading follows the real folds, then re-baseline:

terminal
MF_UPDATE_GOLDEN=1 npm test --workspace @mf/api
×

Do not re-baseline before you have looked at the diff. The goldens are the only regression contract the render service has. Re-baselining an accidental regression bakes it in permanently and silently.

09When something goes wrong

Start at the top of the panel. Almost everything reports itself there.

SymptomCause and fix
Status line is completely blank The script never ran — the panel is rendered HTML and nothing else. Run node tools/build.mjs, then unload and load in the developer tool. If it is still blank, the APP LOGS tab there has the reason.
Build id doesn't match the one the build printed Photoshop is running stale code. Unload and load rather than Reload. If it persists, quit Photoshop entirely — it can hold an old manifest.
“No item.json in that folder” You picked the wrong folder — most often the items directory itself, or an output folder left over from an earlier version. Pick one item directory.
Surface dropdown says “— no item loaded —” Same cause: no valid item is loaded, so there are no surfaces to list. Fix step 2 and this fills in by itself.
“a different shape, not just a different size” The open document's aspect ratio doesn't match the item's canvas, so it is refused rather than squashed. You almost certainly have the wrong file open — use the item's own base.png.
Artwork climbs out of the folds instead of sinking in Displacement sign is inverted. Toggle Flip Y and re-bake.
A logo from the photo is embossed into the result The source wasn't blank. No setting fixes this — mask and fill the print first. See Before you bake.
Shading looks flat and generic after rendering item.json is probably still pointing at the old synthetic maps. Confirm the surface's lighting block names your shadow- and highlight- files.
Result is too subtle in the render Raise Displacement scale and re-bake. It only writes a number into item.json, so this is cheap to iterate on.
Want the original back Rename item.json.bak over item.json. The PNGs are additive and harmless to leave behind.

10Known limits

01

Blank mockups only

Printed artwork in the source photo becomes fake geometry, and no parameter can separate a logo from a fold — they live at the same spatial scale.

02

The maps are not durable

Mockup Forge gitignores assets/items/*/*.png and its Docker build re-runs the seed, so baked maps are untracked and a clean image build will not contain them.

03

One surface at a time

No batch mode. A four-panel van is four passes.

04

Presets are unvalidated

Reasoned from how each material behaves, not fitted against renders. Treat them as starting points.

!

On durability. This predates the baker — the photographic items are already in the same position, since the authoring scripts are never run by the Docker build either. But it does mean re-running the seed, or building a fresh image, discards this work. Commit the PNGs or extend the build before relying on them.
