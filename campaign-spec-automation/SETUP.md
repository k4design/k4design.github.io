# Campaign Spec Automation - Setup

One serverless function, two monday automations. When the Billboard or Digital Ads
column flips to Design Approved, a full build spec appears as an update on the task.

## Verified column mapping (do not trust display names)

| Displayed as | Internal ID | Used for |
|---|---|---|
| Billboard | `dup__of_design1` | Billboard trigger |
| Digital Ads | `dup__of_billboard` | Display trigger |
| Just Listed Mailer | `dup__of_digital_ads` | NEVER trigger on this |
| Design Approved | `date__1` | A date column. Not a trigger. |

Verified against the board schema via API on August 18, 2026. If columns are ever
added, renamed, or rebuilt, re-verify before touching the automations.

## 1. Deploy to Vercel

1. Create a repo (or folder in an existing one) containing `api/spec/[channel].js`.
2. Import it as a Vercel project, or add to an existing project. No build config
   needed; it is a plain serverless function.
3. In Vercel, Settings, Environment Variables, add all three for Production:
   - `ANTHROPIC_API_KEY` from console.anthropic.com, API Keys
   - `MONDAY_API_TOKEN` from monday, click your avatar, Developers, My Access
     Tokens. Use a token from an account with access to board 6530567822.
   - `STACKADAPT_API_KEY` from StackAdapt, Settings, API. If your plan does not
     expose API keys, leave it set to anything; the function degrades gracefully
     and the spec is generated from the playbook without live reference data.
4. Deploy. Note your base URL, for example `https://yourproject.vercel.app`.

Generate and paste the keys yourself. Do not send them through chat or email.

## 2. Create the two monday automations

On the Listing Orders board, Automate, create a custom automation:

**Billboard:**
When **Billboard** changes to **Design Approved**, then **send a webhook** to
`https://yourproject.vercel.app/api/spec/billboard`

**Digital Ads:**
When **Digital Ads** changes to **Design Approved**, then **send a webhook** to
`https://yourproject.vercel.app/api/spec/display`

When you save each one, monday sends a challenge request; the function answers it
automatically, so the webhook verifies on the first try.

Pick the columns in the automation builder by their position and label carefully.
The builder shows display names only, and this board has a date column also named
Design Approved. You want the two STATUS columns.

## 3. Test before trusting

1. Pick a completed order that will not confuse anyone, or create a test item with
   a real address, tier, and links.
2. Flip its Digital Ads column away from and back to Design Approved.
3. Within about thirty seconds an update should appear on the item, headed
   "SPEC GENERATED BY AUTOMATION".
4. Compare that spec line by line against one you would have written. Check the
   name, group, budget reasoning, geo, and the full strip list.
5. Repeat for Billboard and confirm the county list and the empty audience note.
6. Run the next two or three real orders in parallel, automation posting while a
   human still builds, before treating the spec as the source of truth.

## Failure behavior

Every failure posts an AUTOMATION ERROR update on the item itself, so a dead key
or expired token is visible on the task rather than silent. Vercel, Functions,
Logs has the full detail.

## Known limits

- The spec is a build sheet. StackAdapt API access here is read only and the
  campaign is still created by a person, or by browser automation in a session.
- The billboard geo xlsx is not attached to the update. monday updates via API do
  not carry file attachments cleanly. The county list in the update is copy ready,
  and the xlsx is generated from the master template on request.
- Dedupe is best effort within ten minutes per item per channel. Flipping a label
  off and on after ten minutes intentionally regenerates the spec, which is also
  the manual re-run mechanism.
